aidR: Tandem Source export format

library(aidR)

Overview

A Tandem Source export is a folder (possibly zipped) containing CSV files for several data types. Filenames combine the participant, serial number, and export date with a data-type suffix, for example:

[1] "tandem_source_example/XXX_1111111_10Mar2026_1111-BG.csv"                   
[2] "tandem_source_example/XXX_1111111_10Mar2026_1111-Basal-doses.csv"          
[3] "tandem_source_example/XXX_1111111_10Mar2026_1111-Bolus.csv"                
[4] "tandem_source_example/XXX_1111111_10Mar2026_1111-CGM.csv"                  
[5] "tandem_source_example/XXX_1111111_10Mar2026_1111-Hourly-basal-delivery.csv"

Each file records the device type (e.g. Tandem Mobi™ System) and serial number on every row:

How aidR detects this format

Because the headers in a Tandem Source export are language-specific, aidR cannot identify a file from its header names. It relies instead on the structure of the file, and distinguishes between data types by the expected number of columns, which columns are numeric, and, where available, a language-independent keyword such as "Tandem" or "t:slim X2" for the files containing CGM, SMBG and basal rates, as well as "Bolus" for the file containing the bolus data.

Files and the data types they produce

To inspect the raw files, we parse the export with clean = FALSE, which returns the full information provided by Tandem Source:

data <- parse_data(id = "1", paths = path, clean = FALSE)
#> Parsing data for id 1...

Cleaning files

When parse_data is run with clean = TRUE, the cleaned data types are built from the following raw files and attributes:

Cleaned data type Used files Used attributes from clean = FALSE
cgm *-CGM.csv data$cgm
basal *-Basal-doses.csv data$basal
bolus *-Bolus.csv data$bolus
carbs *-Bolus.csv data$bolus
SMBG *-BG.csv data$bg
total_basal *-Hourly-basal-delivery.csv data$hourly_basal
total_bolus *-Bolus.csv data$bolus

Notes

  • CGM and SMBG values are reported in mg/dL or mmol/L depending on the account settings; aidR converts them to mg/dL automatically.
  • timezone_offset is always NA, since Tandem Source exports report only local (wall-clock) time.
  • The device type is stored as pump_name for insulin data and sensor_name for glucose data.
  • The hourly basal file reports the basal insulin delivered in each hour of the day, one row per day and one column per hour. aidR sums the 24 hourly columns into total_basal, which therefore carries source = "reported". total_bolus, in contrast, is summed from the cleaned bolus data and carries source = "summed".
  • Because basal durations are inferred from consecutive timestamps, the final basal entry of an export has no successor and its duration is therefore unknown.
  • Each row of the bolus file holds a bolus together with the carbohydrates entered for it, so bolus and carbs are linked by link_id. Boluses without carbohydrates have link_id = NA.
