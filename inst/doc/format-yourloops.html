aidR: YourLoops export format

library(aidR)

Overview

A YourLoops export is a folder (possibly zipped) containing CSV files for several data types:

 [1] "alarms.csv"                      "basal.csv"                      
 [3] "bolus.csv"                       "cbg.csv"                        
 [5] "meals.csv"                       "physicalActivities.csv"         
 [7] "rescuecarbs.csv"                 "settings-cgm.csv"               
 [9] "settings-current-parameters.csv" "settings-device.csv"            
[11] "settings-pump.csv"               "settings-security-basals.csv"

The column headers are always in English, regardless of the user’s account language. Timestamps are given in UTC alongside a separate timezone offset in minutes, so recovering local (wall-clock) time requires combining the two. This example shows a file containing CGM data:

timestamp,timezoneOffSet,value,units,cgmModel
2025-07-06T00:00:18Z,120,165,mg/dL,
2025-07-06T00:05:17Z,120,167,mg/dL,
2025-07-06T00:10:17Z,120,166,mg/dL,
2025-07-06T00:15:17Z,120,168,mg/dL,
2025-07-06T00:20:18Z,120,163,mg/dL,
2025-07-06T00:25:19Z,120,155,mg/dL,
2025-07-06T00:30:19Z,120,154,mg/dL,
2025-07-06T00:35:19Z,120,152,mg/dL,
2025-07-06T00:40:19Z,120,151,mg/dL,

How aidR detects this format

Because YourLoops headers are language-independent, aidR identifies each file by matching its column names exactly against a lookup of the expected headers for each data type.

Files and the data types they produce

To inspect the raw files, we parse the export with clean = FALSE, which returns the full information provided by YourLoops:

data <- parse_data(id = "1", paths = path, clean = FALSE)
#> Parsing data for id 1...

Note that a YourLoops export contains no SMBG data; cgm, basal, bolus, and carbs are the core data types available from this platform.

Cleaning files

When parse_data is run with clean = TRUE, the cleaned data types are built from the following raw files and attributes:

Cleaned data type Used files Used attributes from clean = FALSE
cgm cbg.csv data$cgm
basal basal.csv data$basal
bolus bolus.csv data$bolus
carbs meals.csv, rescuecarbs.csv data$meals, data$rescuecarbs
total_basal basal.csv data$basal
total_bolus bolus.csv data$bolus

Notes

  • CGM values are reported in mg/dL or mmol/L depending on the account settings; aidR converts them to mg/dL automatically.
  • When clean = FALSE, timestamps are reported exactly as in the file: the timestamp column is in UTC and the timezoneOffSet column gives the offset, so local (wall-clock) time is obtained by adding the two.
  • When clean = TRUE, for consistency with the other formats the timestamp column instead holds local (wall-clock) time, while timezoneOffSet remains the same offset. UTC time can therefore be recovered by UTC = timestamp - timezoneOffSet.
  • YourLoops reports no daily insulin aggregate, so total_basal and total_bolus are summed from the cleaned basal and bolus data and carry source = "summed".
  • Biphasic (dual-wave) boluses are exported as two separate rows rather than one combined event. aidR keeps them separate but flags them, so they can be recombined if needed.
  • link_id is always NA for bolus and carbs: the export does not record which carbohydrate entry triggered which bolus. Matching them by timestamp and amount is not implemented.
